# F103 运行时资源与时序预算

审查日期：2026-10-06。目标为 STM32F103C8T6、64 KiB Flash、20 KiB SRAM。当前完整通信业务的 Keil 独立工程链接结果为 **Flash 22,000 字节、RAM 9,296 字节（包含 4,096 字节栈，堆为 0）**；115200 与 460800 两个启用业务的隔离链接配置尺寸相同。依据为 [编译报告](../reports/stm32_standalone.json) 中的 `ground_f103/enabled_link_only`、`enabled_link_only_460800`，以及 [115200 map](../reports/stm32_standalone/enabled_link_only/ground_f103.map) 和 [460800 map](../reports/stm32_standalone/enabled_link_only_460800/ground_f103.map)。交付默认仍为 `DC_BOARD_READY=0`；上述 `READY=1` 仅用于隔离副本的链接检查，未生成可烧录交付包。尚未烧录或测量栈峰值，**本文件不代表 RAM 或时序实板验收通过**。

## SRAM：链接静态分配 5,200 字节，已预留 4 KiB 栈

使用 SDK 2017.4 自带 ARM GCC 6.2.1、`-mcpu=cortex-m3 -mthumb` 和真实 F1 HAL/CMSIS 头，从标准输入编译以 `sizeof` 定长的字节数组，再用 `nm -S` 读取 ARM ABI 尺寸；同时用现有 `ground_f103_*.o` 的全局符号和 Keil map 复核。临时测量对象仅写入忽略的 `build/`，没有修改固件源码。类型表用于解释构成，最终 Flash/RAM 分配以完整工程的 Keil map 为准。

| 对象 / 类型 | ARM ABI 字节数 | 计入方式 |
| --- | ---: | --- |
| `dc_stm32_app_t` 全体 | 4,916 | `main_hooks.c` 的静态 `app`；包含下面的节点、两组 UART、解析器和无线对象 |
| `dc_node_t` | 592 | 已包含在 app 中，包括 peer 状态、缓存回复和最新遥测/状态帧 |
| `dc_stm32_uart_t × 2` | 1,732 × 2 = 3,464 | 已包含在 app 中；F103 实际仅使用 USART2，但当前通用 app 仍为两路分配存储 |
| 每路 UART 的字节环形缓存 | 1,040 | 已包含在各 UART 对象中；其中数据 1,024 字节，其余为索引、故障和统计 |
| 每路 UART 的 DMA 缓冲 / TX 编码缓冲 | 256 / 48 | 已包含在各 UART 对象中 |
| 每个帧队列 `dc_queue_t` | 360 | 两个 UART TX 队列及一个 RF TX 队列，共 1,080 字节，均已包含在 app 中 |
| `dc_parser_t × 2` | 72 × 2 = 144 | 已包含在 app 中 |
| `dc_radio_t` | 220 | 已包含在 app 中，包括请求、计时器、统计和 RSSI/LQI |
| 单帧 `dc_frame_t` | 44 | 内存结构尺寸；通过显式编码产生 14–46 字节消息体，不能直接把结构体内存发往空口 |
| app 之外的无线 SPI bus | 24 | 单独静态对象，含故障恢复所用的 CR1 配置快照 |
| `huart2` / `hspi1` / `hdma_usart2_rx` | 72 / 88 / 68 | 单独 HAL 全局对象，共 228 字节 |
| `dc_firmware_started` | 1 | 单独全局标记 |
| 当前 F1 HAL 的 tick 全局对象 | 9 | `uwTick`、`uwTickPrio`、`uwTickFreq`，未包含在 app 中 |

上述不同全局对象合计 **5,178 字节**，app 的子项仅说明构成，不能再次加到 4,916 字节上。完整链接的非栈 RAM 分配为 **5,200 字节**，差额 22 字节由 `SystemCoreClock` 4 字节、`dc_startup_status` 4 字节和链接对齐 14 字节组成。无线寄存器 profile 是 92 字节只读常量，正常链接到 Flash。

当前通信源代码没有 `malloc/calloc/realloc`，没有 RTOS 线程栈。独立工程 startup 已设置 **栈 4,096 字节、堆 0 字节**；静态分配与栈合计 9,296 字节，约 9.08 KiB，20,480 字节 SRAM 尚余 **11,184 字节**。Flash 尚余 **43,536 字节**。这些是当前链接配置的剩余地址空间，不是栈峰值验证；接入额外模块、动态分配或复杂格式化输出后应重新计算。

当前调用链有界，没有业务递归。尚未完成最终编译配置下包含主循环、回调、HAL 嵌套和中断压栈的最坏调用链分析，也没有板上栈水位测量，因此不能仅凭单函数栈帧或 RAM 空余量证明 4 KiB 栈足够。

本轮独立工程已用严格 scatter 和 `.map` 验证当前业务的 RAM/Flash 范围及 4,096 字节栈，未使用 CCM 或外部存储。最终集成后仍要复核 DMA 位于普通 SRAM，并以栈填充水位验证中断与收发同时运行时的峰值。静态库本身不会执行这些链接范围检查。

## CC1101 FIFO 与空口时长

| 内容 | 最大字节数 |
| --- | ---: |
| 原生协议消息体：头 12 + payload 32 + 软件 CRC 2 | 46 |
| 长度字段表达的内容：RF 地址 1 + 消息体 46 | 47，等于 PKTLEN `0x2F` |
| 写 TX FIFO：长度字段 1 + 地址和消息体 47 | 48 |
| 读 RX FIFO：以上 48 + RSSI 1 + LQI/CRC_OK 1 | **50 < 64**，余量 14 |

CC1101 硬件 CRC 在空口自动产生/校验，不额外占用上述 RX FIFO 的数据长度；UART 的 COBS 编码和 `0x00` 分隔符不进入空口。最大包可一次放入 FIFO，无须在 ISR 中边传边补充 FIFO。

在实际寄存器速率约 38.3835 kbps 下，最大空口包包含前导 4、同步 4、长度 1、地址 1、消息体 46、硬件 CRC 2，共 58 字节，约 **12.09 ms**。该计算不含校准、频率合成器切换和软件排队。空载遥测查询约 5.42 ms，16 字节模拟遥测回复约 8.75 ms。20 ms TX 看门狗因此需实测确认其校准、SPI 和轮询余量；30 ms 回复等待从确认 TX 完成后开始，整个事务截止期固定 200 ms。

## 轮询与阻塞预算

主循环每次处理一个无线接收包和每路最多 128 个 UART 字节；状态寄存器每次最多读取 4 次寻找相邻一致值。ISR 仅采集 DMA 字节、记录发送完成或 GDO 事件。没有无界业务队列，也没有等无线回复的阻塞循环。

F103 当前 SPI1 为 72 MHz / 32，即 2.25 MHz。两个字节的寄存器传输仅约 7.1 μs，51 字节的 FIFO 命令和数据仅约 181 μs。因此健康设备的正常轮询预计可满足约 1 ms 调用目标，**这仍是计算预期，需要实测，不能表述为已保证的硬实时上界**。

底层 MISO-ready 最多等待 2 ms 或 10,000 次轮询。SPI 由 HAL 完成初始化，实际收发走工程自有 `dc_spi_poll8.h`：一整次传输共用 **2 ms 截止时间和 4,096 次轮询预算**，所有字节的 TXE、RXNE 和最后 TXE、BSY 均受该预算约束，即使标志已就绪也先检查截止期。支持 1–64 字节，并拒绝非 master/双线/8-bit/mode-0/MSB/软件 NSS、SPI CRC 或 TI 模式开启的配置。

错误退出采用 DR→SR→保存的 CR1，清理 OVR/RXNE/MODF 并恢复 MSTR/SSI/SSM、禁用 SPE；下一次传输重新启用 SPE。初始 HAL 配置的 CR1 快照保存在 SPI bus 中，因此 MODF 清掉硬件 MSTR/SPE 后，CC1101 故障重新初始化仍能继续收发，不依赖再次调用 MCU 的 `HAL_SPI_Init()`。原先依赖 HAL 收尾辅助函数无符号剩余时间计算的路径已替换，官方 HAL 文件未修改；寄存器/时钟 fixture 验证了停滞标志、冻结时间、OVR/MODF、截止期相等和同一对象 MODF 后恢复。

SRES 的三阶段 CSN 脉冲共享 **65,536 次迭代预算**，每段要求 1 ms tick 差，并用 `SystemCoreClock/25000+1` 个 NOP 保证至少 40 μs 下限；时间停滞会耗尽预算并释放 CSN 返回失败。SRES 后另有 2 ms / 10,000 次 MISO-ready 等待。通信业务的心跳和事务截止期仍要求 SysTick 持续前进；最终工程应保留正确的 `HAL_IncTick()`。

以中断调度正常、底层预算如期生效为前提，单个寄存器或普通 strobe 的粗略预算是 4 ms，FIFO burst 使用两次自有 SPI 传输，预算是 6 ms。累加多个底层调用后：

- 已就绪 RX 收包：状态读取、分别读长度和数据、回到 RX，极端慢但仍成功时约 52 ms；错误包需要清 FIFO 时约 60 ms。
- RX_START 正好遇到已收完包，还需再次读取 RXBYTES，保守预算可达约 76 ms。启动一次 TX 约 34 ms；轮询中进入一次重试约 66 ms。
- SRES 与完整 profile 重配置：46 组配置写入和读回、芯片身份、地址、PATABLE、SRES 和 SCAL 的总调用预算约 0.42 s。正常设备应远短于该值。该路径同步执行，除启动和 FAULT 重初始化外，**异常 TX 超时、下溢、发送中取消，以及状态无法确认时的恢复也可能进入该路径**，因此不能用上面的普通 RX/重试预算覆盖这些故障场景。平台每 500 ms 最多尝试一次的限制仅针对 app 中的 FAULT 重初始化，不适用于每次 TX 异常恢复。

上述是按调用次数累计的审查估算，不是测得的执行时间，也不是对任意中断占用的绝对 wall-clock 保证。新 SPI、CSN 和 SRES 路径都有迭代后备上限，消除了已发现的无符号剩余时间下溢和复位延时死等问题；多个成功操作仍可能累计延迟，软件看门狗仍只能在主循环获得执行时处理。PC 无线 mock 不在 SPI 回调内推进时间，不能据此证明 20/30/200 ms 的实板截止期成立。实际 GPIO、SPI 频率、编译优化和中断占用都会影响执行时间，需用实板测量确认。

当前默认 115200 bps、8N1，满速输入约 11,520 字节/秒；256 字节 DMA 半缓冲约 11.11ms，1,024 字节软件环约容纳 88.9ms，48 字节最长 UART 帧约 4.17ms。地面 F103/F407/Zynq 首测后一起切到 460800 复测，下列更严格预算继续适用。

460800 bps、8N1 的满速输入约 46,080 字节/秒。每路 256 字节 DMA 的半缓冲事件间隔约 **2.78 ms**，中断必须及时采样；1,024 字节软件环形缓存仅能容纳约 **22.2 ms** 的连续满速输入。SPI 同步恢复期间中断仍可采集 UART 数据，但主循环可能来不及消费，软件环会溢出；当前程序会标记故障、丢弃受影响字节并在分隔符处恢复解析。DMA 采样仍需至少每半缓冲一次，若中断延迟导致 DMA 完整转过一圈，仅靠 NDTR 不能保证检出全部丢失。这是丢包后恢复策略，不能保证故障期间零丢包。上述 UART 时间均为容量估算，须实测最大 ISR 延迟、主循环停顿和满速输入丢包情况。100 ms 查询忙时跳过；无线重试不会新增事务或延后原始截止期。

## 实板必须记录的项目

- 最终 `.map` 中的 RAM/Flash 使用、栈/堆设置和 DMA 所在区域；并发收发、坏帧及重新初始化期间的栈水位。
- 用计时器或调试 GPIO 测量主轮询最大间隔、状态读、FIFO 读写和故障重初始化耗时。记录 SysTick、UART/DMA 和 GDO 中断同时触发时的情况。
- 测量 GDO TX 包结束、主循环确认完成、地面进入 RX 和机载开始回复的相对时间；最大 TEST_RESULT 包应在 20 ms TX 预算内完成，地面应在机载同步字到达前进入 RX。
- 连续满速 UART、无线 CRC 错误、溢出、断电重连、SPI MISO 不就绪及重初始化场景下的 UART/RF 错误计数、丢包、解析恢复和重新握手结果。尤其不能用 PC 虚拟时间测试代替这些时序验收。
